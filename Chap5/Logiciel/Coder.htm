Cette section traite de la manière d'écrire et de documenter le code de programmes de langages procéduraux comme Matlab. Le codage représente une traduction des spécifications du programme dans le langage de réalisation Matlab.

Aspects psychologiques

Comme il faut s'efforcer de penser selon le langage de traduction, l'écriture de programmes permet une meilleure compréhension de la science de l'informatique. Toutefois, le codage implique des considérations psychologiques, qui se manifestent non seulement avec l'utilisation de Matlab, mais avec tous les langages de programmation.

  • L'écriture d'un programme représente un travail de traduction.
  • L'interprétation des structures peut être perçue différemment par un humain et par le compilateur. Doté d'un langage technique limité, l'ordinateur est un robot qui peut difficilement reconnaître une qualité sémantique à ce qui est écrit.
  • Comme la reconnaissance des structures est globale chez l'humain, il est plus facile de percevoir une structure lorsque les instructions sont regroupées linéairement en blocs. Le codage doit respecter ce trait psychologique de l'humain.
  • La linéarité est une autre caractéristique humaine qui est facilitée par l'écriture de suites de séquences logiques. Il faut donc éviter les instructions qui ne tiennent pas compte de ce principe; par exemple des instructions Goto, Return ou Break qui peuvent provoquer des sorties anormales des structures de boucle, de décision ou de fonction.
  • L'apprentissage d'un langage influence la manière de communiquer avec un ordinateur. L'habitude et la tradition peuvent affecter la créativité dans le processus d'utilisation d'un nouveau langage. Il va de soi que la connaissance de plusieurs langages influence la manière de concevoir un projet informatique.

Éléments de style

L'écriture de textes en français nécessite rigueur, concision et clarté. Ces considérations s'appliquent à l'écriture du code informatique. Le style est une qualité importante du code et affecte l'intelligibilité du programme.

Le programme doit aussi contenir une documentation interne, des méthodes pour déclarer les variables, des outils pour la construction de structures et l'utilisation des données. En s'appuyant sur les considérations psychologiques, voici des critères à respecter lors de l'écriture de programmes.

Documentation

Le programme n'est habituellement pas écrit dans notre langue maternelle. C'est plutôt le résultat d'une traduction et d'une interprétation des spécifications. Le programme doit donc être écrit de façon à être lisible et facile à interpréter. Écrire pour être compris.

Documenter un programme ne veut pas dire ajouter des commentaires après la rédaction du programme.

Écrire un programme structurée :
  1. En-tête
    • L'instruction help de Matlab affiche les lignes de commentaires depuis le début du fichier (après l'instruction function) jusqu'à la première ligne de code. Le prologue d'une fonction indique ce qu'elle accomplit.
    • Fournir le nom de l'auteur et, le cas échéant,  les dates de modifications.
    • Tout programme doit avoir un en-tête; ceci est un strict minimum.
  2. Explications
    • Pour une fonction, inclure une description des arguments et, au besoin, un exemple d'utilisation.
    • Lister les variables pertinentes, leur utilisation ainsi que leur limitation.
    • Ajouter également la liste de toutes les sous-fonctions externes utilisées.
  3. Déclarations
    • En Fortran ou en C, il faut déclarer toutes les variables au début du code du programme.
    • Dans Matlab, bien qu'il soit permis d'utiliser des variables sans déclaration préalable, déclarer au moins tous les tableaux à l'aide des fonctions zero ou ones. Cela améliore grandement l'efficacité du code et évite de fragmenter la mémoire. 
  4. Lignes de code
    • Écrire pas plus de 50 lignes de code (une page d'impression) par fonction.
    • Éviter d'écrire plus d'un énoncé par ligne, car c'est plus difficile à lire et à interpréter.
    • Ne pas dépasser 60 colonnes par instruction, car c'est plus difficile à lire (et à imprimer). Une ligne d'instruction Matlab peut se continuer en ajoutant trois points...
    • Indenter les lignes de code dans les structures de contrôle.
      • Deux à cinq espaces suffisent.
      • Utiliser un outil automatique, tel l'éditeur de Matlab, pour cette tâche répétitive.
      • Reformater au besoin. Dans l'éditeur de Matlab, il suffit  d'appuyer sur les touches Ctrl-A et Ctrl-I pour effectuer une indentation automatique de tout le fichier en édition.
Commenter le code s'il y a lieu
  • En français, chaque mot a un sens, tout comme dans un programme.
  • Choisir des noms de variables significatifs
    • La documentation interne d'un programme débute par le choix judicieux, bref et précis des noms de variables.
    • Exemple :
      B - trop court comme nom d'une variable importante
      Indice - un peu long comme indice de variables, utiliser i, j ou k
      Compteurs - le pluriel est étrange
      Suite_num - qu'est-ce que ça signifie ?
      x - c'est probablement l'abscisse ou l'argument d'une fonction y = f(x); si c'est autre chose, choisir un autre nom de variable.
  • Ajouter des commentaires pertinents :
    • sans exagérer et en évitant les évidences,
    • en les écrivant en retrait, afin de ne pas nuire à la lisibilité,
    • en n'oubliant pas d'effacer ceux qui ne sont plus utiles,
    • en évitant de paraphraser le code (irritant),
    • en décrivant des blocs de codes plutôt que de commenter chaque ligne.
  • Un programme lisible contient habituellement peu de commentaires dans la portion code.

Données - types - tableaux - arguments

  • Matlab permet de modifier le type d'une variable en cours de programme, mais il faut éviter de le faire.
  • Ne pas utiliser la notation matricielle pour une variable représentant un vecteur,
  • Déclarer les tableaux chaque fois que c'est possible.
    Exemple :
    • Une boucle comptée doit créer une à une  n valeurs de A et B et les manipuler.
      • for i=1:n
           A(i)=...
           B(i)=...
        end
    • Matlab recopie ailleurs dans la mémoire tout le vecteur chaque fois qu'il y a ajout d'un élément. Cela consomme temps et mémoire.
    • Déclarer : A = zeros(n), B = zeros(n)
      Matlab réserve l'espace nécessaire aux vecteurs et ils ne sont pas recopiés n fois pendant la manipulation.
  • Une valeur numérique qui ne change pas est définie par une constante. Exemple :
    • S'il y a n données à lire, ne pas écrire 50, parce qu'il y a 50 données dans le fichier. Si le fichier change, le programme ne s'exécute pas correctement. Laisser le programme déterminer la valeur de n.
    • Au lieu de abs(A-B) < 0.001, écrire
      epsilon = 0.001 au début du programme et
      abs(A-B) < epsilon.
  • Une fonction ne modifie jamais la valeur des arguments reçus.
    • L'argument est un paramètre passé en valeur, ce qui permet d'éviter qu'une modification apportée dans la fonction ne modifie le tableau de la partie appelante.
    • Pour être plus efficace, Matlab examine le code de la fonction pour déterminer si des modifications sont apportées à l'argument. S'il n'y en a pas, Matlab passe l'adresse mémoire de l'argument sans effectuer de copie. Il y a donc une économie de temps d'exécution ainsi que d'espace mémoire.

Structures de contrôle et calculs

  • Écrire des conditions simples.
    • Éliminer les tests sur des conditions négatives.
    • Éliminer une instruction else sans autre instruction.
      • Exemple :
        if (...)
           instructions
        else
        end
    • Éviter d'imbriquer trop de conditions ou de boucles.
    • Utiliser des parenthèses pour clarifier des expressions logiques ou des expressions arithmétiques.
    • Ne pas mélanger les types de données.
    • Retirer toutes les expressions exécutables à l'extérieur d'une structure de contrôle.
  • Espaces et lignes vides
    • Utiliser des espaces seulement pour clarifier la lecture.
    • Utiliser des lignes vides pour séparer les blocs. Par contre, il faut éviter d'en mettre partout, car elles diminuent le nombres de lignes de code visibles à l'écran. Et il y a risque de réduire la perception globale des blocs d'instructions.
    • Indenter les lignes à l'intérieur des structures de contrôle.
    • Mettre un espace avant et après le symbole d'égalité, ou un opérateur de relation.
    • Mettre des espaces dans les expressions ou les commentaires, comme en français.
  • Utiliser des expressions entières ou booléennes, lorsque c'est possible.
  • Utiliser des variables intermédiaires, pour simplifier une expression arithmétique jugée trop longue.
    • Pour une fraction, écrire une ligne pour le numérateur et une autre pour le dénominateur.
    • Une longue ligne d'instruction peut être étalée sur plusieurs lignes, à l'aide de l'instruction de continuation {...}.
  • Effectuer des opérations vectorisées lorsque c'est possible.
  • Sans sacrifier la lisibilité, simplifier le plus possible.

Entrées et sorties

  • Indiquer l'organisation des données, les entrées et les sorties utilisées par le programme ou la fonction.
  • Les sorties d'un programme doivent faire du sens pour l'utilisateur.
  • Valider les entrées ou les combinaisons.
  • Uniformiser la manière de lire ou d'écrire.
  • Utiliser une donnée sentinelle ou la fin d'un fichier plutôt que demander à l'utilisateur de spécifier le nombre de données à lire.
  • Utiliser le moyen de lecture ou d'écriture le plus simple.

Mise au point du code

  • Écrire des petits bouts de programme à la fois, et les tester au fur et à mesure.
  • Corriger une ligne à la fois. Très souvent, une instruction fautive tire son origine des lignes qui précèdent ou qui suivent.
  • Efficacité :
    • C'est une spécification implicite et requise dans un programme.
    • Une bonne conception améliore l'efficacité d'un programme.
    • La clarté du code ne doit pas être compromise par des trucs visant à améliorer l'efficacité.
    • Un code simplifié améliore l'efficacité.

Organiser un programme en  fonctions

Un programme est défini comme une séquence d'instructions destinées à résoudre un problème. La plupart des solutions aux exercices des chapitres précédents nécessitent la rédaction d'un programme qui comporte un seul script.

L'expérience démontre qu'il faut parfois décomposer un problème en parties pour produire une solution. De plus, dès qu'un programme dépasse cent lignes d'instructions, il devient plus difficile à gérer, et il convient de le diviser en portions significatives.

Pour organiser méthodiquement un programme en plusieurs étapes et pour simplifier la résolution d'un problème, Matlab propose de diviser le programme en fonctions. Chacune constitue un véritable petit programme regroupant une séquence d'instructions qui accomplit une tâche précise dans la solution du problème.

Avantages
  • La fonction regroupe des instructions qu'il suffit d'écrire et de mettre au point une seule fois. La mise au point de chacune s'effectue de manière indépendante du reste du programme, ce qui diminue les risques d'erreurs.
  • Les  variables ont des noms locaux, c'est-à-dire que le même nom de variable peut se retrouver dans plusieurs fonctions, tout en ayant une valeur indépendante et différente dans chaque fonction.
  • Il est possible d'utiliser la même fonction plus d'une fois à l'intérieur d'un programme.
  • La programmation par fonction permet le partage et le regroupement de plusieurs fonctions spécialisées dans la résolution de tâches similaires : c'est l'ensemble de fonctions (toolbox).
Programme principal

C'est le script qui lance l'exécution d'un programme, et dans un programme bien structuré, c'est également le script qui termine l'exécution du programme. Dans un long programme, sa tâche principale consiste à gérer les fonctions afin de réaliser de façon ordonnée les différentes étapes nécessaires à la solution du problème.
